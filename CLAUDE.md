# Kyiv Badminton Olimp — project instructions

@OLIMP-DESIGN-SYSTEM.md

## Architecture (контент + шаблон + сборка)

* Весь контент сайта хранится в `content/site.json` — единственный источник правды. Его редактирует админ-панель `/admin` (коммитит файл в GitHub через `/api/content`).
* Разметка — в `templates/index.html` (бывший `index.html`). Синтаксис: `{{путь}}` — экранированный текст, `{{#список}}…{{/список}}` — цикл/условие, `{{^поле}}…{{/поле}}` — «если пусто». Сырой HTML из JSON не выводится.
* `npm run build` (`scripts/build.js`) валидирует JSON по схеме и собирает статический сайт в `dist/` (HTML + `css`, `js`, `assets`, `site-materials`, `admin`). Vercel запускает сборку сам (`vercel.json`), `dist/` в git не хранится.
* `lib/schema.js` — схема контента: поля, подписи админки, допустимые цвета, валидация. Используется и сборкой, и сервером, и админкой — формы админки генерируются из неё.
* Добавление/изменение редактируемого поля: 1) поле в `lib/schema.js`, 2) значение в `content/site.json`, 3) плейсхолдер в `templates/index.html`. Производные значения (колонки, даты, абзацы) — в `toViewModel` в `scripts/build.js`.
* Цветовые варианты карточек в схеме должны совпадать с классами из `css/style.css`. Новый вариант — только вместе с CSS и обновлением `OLIMP-DESIGN-SYSTEM.md`.
* `api/` — Vercel Functions (`login`, `logout`, `content`, `upload-token`), общий код в `lib/` (`auth.js`, `http.js`, `store.js`). Секреты только в переменных окружения (см. `.env.example`), никогда в коде.
* `admin/` — отдельная страница со своим CSS; стили публичного сайта не трогает. Все надписи — українською.
* Локальная проверка: `npm run dev` (сервер `scripts/dev-server.js`, `.env` с `CONTENT_STORE=local` пишет в локальный `content/site.json`).
* После правок шаблона: собрать сайт и проверить `dist/index.html` на 1440 / 768 / 375 px.

## Design rules

* Перед созданием или изменением любой пользовательской секции, компонента, карточки, заголовка, текста, кнопки, изображения, видео или анимации сначала сверяйся с `OLIMP-DESIGN-SYSTEM.md`.
* `OLIMP-DESIGN-SYSTEM.md` является главным источником правил по цветам, типографике, сетке, отступам, карточкам, кнопкам, изображениям, видео, анимациям и адаптивности.
* Применяй дизайн-систему автоматически, даже если пользователь не повторяет это требование в новом задании.
* Не создавай новые визуальные стили, цвета, шрифты, размеры, радиусы, тени или принципы анимации, если задача может быть решена средствами существующей дизайн-системы.
* Если запрос пользователя намеренно меняет дизайн-систему, сначала реализуй согласованное изменение, а затем обнови `OLIMP-DESIGN-SYSTEM.md`, чтобы документ соответствовал фактическому сайту.
* Не изменяй уже утверждённые секции, если пользователь прямо не попросил их изменить.
* При работе только над одной секцией не затрагивай остальные части сайта.

## Language

* Все тексты, видимые посетителю сайта, должны быть на украинском языке.
* Русский язык в пользовательском интерфейсе запрещён.
* Допускаются только короткие английские фразы как декоративные элементы.
* Технические отчёты пользователю можно писать на русском языке.

## Responsive checks

После каждого визуального изменения проверяй сайт на ширинах:

* 1440 px;
* 768 px;
* 375 px.

Обязательно проверяй:

* отсутствие горизонтальной прокрутки;
* читаемость текста;
* отсутствие перекрытий;
* мобильную навигацию;
* правильную работу анимаций;
* `prefers-reduced-motion`;
* отсутствие ошибок в консоли.

## Project materials

* Не изменяй и не удаляй исходные файлы в папке `site-materials`.
* Не придумывай отсутствующие ссылки, адреса, отзывы или контактные данные.
* Не используй визуальные референсы как готовые изображения сайта, если они обозначены только как референсы.

## Git

* Не создавай коммит без отдельной команды пользователя.
* Не выполняй push без отдельной команды пользователя.
